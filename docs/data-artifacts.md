# Data Artifacts

Everything lives in `data/`. Most files are gitignored (regenerable via `manamap run`); the ones the deployed viz fetches are **git-tracked** via explicit `.gitignore` exceptions.

**Do NOT move these to Git LFS.** The viz is served by GitHub Pages straight from the repo, and Pages serves LFS pointer files, not content — LFS would silently break every data fetch on the deployed site.

`membership` is two positional arrays (`l0`, `l1`), one entry per card in `cards.csv` row order, `-1` for noise — so it inherits the index-alignment invariant and `membership.l0[i]` describes `cards.csv[i]`. Cluster id *n* at level *L* is the region with `id == "lL_n"`. This is the only thing in the repo that can answer *which region is this card in*; before it existed the viz could draw a region's name but never its members. **Noise is a real answer, not a gap**: 29% of cards on the default map belong to no L0 region, and they are left at `-1` rather than snapped to a nearest centroid they were never clustered into.

`w` and `h` are the bounding box beside `span` (which stays `max(w, h)` and still drives label culling). Collapsing them discarded aspect ratio, the one signal distinguishing a filament from a blob — a 20×1 streak and a 20×20 cloud serialised identically. With both axes kept, the map's roads are measurable: `White Enchantments — Auras — ETB` is 209 cards at 1.6 × 0.1, a 16:1 streak.

N = card count, ~34,900 as of August 2026; grows as Scryfall adds sets.

**"Tracked" no longer means "the viz fetches it."** It did until Deck Building v2 added
`combo_details.json` and `card_roles.json`, which are tracked because the deck builder and
the agents need them on a fresh clone, but which the browser never touches.

**And "the viz" is now two pages with two registries.** The card map (`viz/index.html`)
fetches from the twelve-entry `DATA` map in `viz/js/mana-map.js` (only three land on the discovery boot: `viz_index.json`, `neighbours.bin` and the projection; `card_roles.json` is lazy). The deck dossier
(`viz/deck.html`) fetches a disjoint set through its own `FILES` map in
`viz/js/deck-view.js`: `data/decks/index.json` first, then `info.json` plus the per-deck
artifacts — including every file in `sim/`, `experiments/`, `prescriptions/` and
`decisions/`, **which the manifest has to name because a browser cannot list a directory**.
That is why `build_index` emits `sim_runs`, `experiments`, `prescriptions`,
`decision_files` and a `has` block of presence flags alongside the stack filenames it
always carried; `getJSON` swallows a 404 to `null`, so without the flags "no artifact" and
"request failed" are the same answer. See `docs/viz.md`.

Note also that **`cards.csv` is gitignored but load-bearing for the builder**: it is the
only home of the `game_changer` column (WotC's Game Changers list, via Scryfall), so
`bracket-check` needs a pipeline run even though rendering a manual doesn't.

A RENDERING, never a replacement: the raw note stays authored and reachable behind every entry, and `log_annotations.json` remains the machine-readable reading the doctor consults. It is the ONE artifact here that does not go stale when the deck changes, which is why it has no `deck_status.STAGES` row and why `cards:semantic` is deliberately absent from its cache routine), `experiments/<id>.json` (**the flagship** — a controlled A/B of two versions against the same table — both arms' decklist text, analysis and per-game rows (`games_detail`), and a `delta` in which EVERY figure carries an interval on the DIFFERENCE — Newcombe for proportions, Welch plus a permutation p for means, a bootstrap on the median for the skewed ones — plus a `power` block giving the minimum detectable difference at that N. It used to report whether the two arms' marginal intervals overlapped, which is the overlap fallacy; that key is removed rather than deprecated. Only `win_rate` is pre-registered and carries a verdict. Logs beside it gitignored and exactly regenerable), `sim/<run-id>.json` (a Forge simulation run — ◆ SEEDED since `-s` was found, SAMPLED on the earliest records: outcomes, per-game rows, `analysis` with Wilson/normal intervals and its `limits`, every seat's decklist sha, engine versions, and the assumptions incl. The key inside is `forge_ai_targeting_policy`, not something shorter, because it measures Forge's AI rather than human politics and a key cannot be paraphrased away; `limits[]` carries the engine caveat as the imported constant. Empirical opponent modelling, never an equilibrium), `prescriptions/<id>-*.json` (one question to the doctor — AUTHORED prompt + the doctor ⇄ skeptic answer in one file; accumulating, never overwritten; `validate-prescription` form-checks stale ones). **The workbench surface:** `info.json` (what `viz/deck.html` fetches — `deck-info --write`'s composed join of status, bracket, goldfish, engine, audit, diagnosis, sim, experiments, prescriptions, open questions and the derived `next`. The only COMMITTED artifact composed from every other one, so it is staleness-gated by recomputation rather than by a stamp; it **omits the version block**, because versions are a git walk and a committed copy is one commit behind forever). **Measurement and proof:** `goldfish_targets.json` (the engine DECLARATION — `validate-goldfish-targets` checks it), `goldfish_metrics.json` (◆ seeded), `benchmark.json` (◆ — the STANDARD BENCHMARK, PRD-v1 §9: four measures under one FROZEN configuration whose version rides in the record. Deterministic, so it is tracked and freshness-gated. ## Consistency invariant

`projection[i]`, `embeddings[i]`, and `cards.csv[i]` all refer to the same card by **position**. Never partially regenerate after the card count changes — re-run the pipeline from the changed step onward (see `docs/pipeline.md`). The integration tests (`tests/test_pipeline_integration.py`) assert cross-artifact count consistency.

## Paths

All paths are defined in `src/manamap/config.py`, anchored to the repo root via `__file__` (CWD-independent). Override with `MANAMAP_DATA_DIR` / `MANAMAP_VIZ_DIR` env vars for sandboxed runs.
