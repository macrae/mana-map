# The evidence contract

Stacks, citations, `engine.json`, the deck map, and every validator's reasoning — including the checks that were prototyped and REJECTED for firing on correct data. Read before adding a validator or a claim.

Extracted verbatim from `CLAUDE.md` — every measurement here was in that file and none was reworded. `CLAUDE.md` loads into every session; this does not, so the rules that bite regardless of what you are touching stayed there and the full record moved here.

- **A field is only as revisable as it is short — `MAX_WHAT_IT_DOES = 1800`.** Radagast's `output` stage reached 2,554 characters by accreting narration of its own previous drafts, and then **failed four consecutive revisions**: each fixed the defect it was sent to fix and introduced a new one. The six stages that were never revised ran 836–1,645. Past roughly a page an agent asked to change one clause cannot hold the rest of the argument in view — that is a hard editing task disguised as a small one, not sloppiness. The sixth revision, cut to 1,704 by deleting draft narration rather than findings, passed first try. **The limit is measured, not fitted: the tracked artifact failed it the moment it was added.**
- **Two validators can make an artifact impossible to write, and nothing notices if neither is gated.** `validate_stack` requires a `strategy:` citation to be VERBATIM; `validate_issue` forbids an internal taxonomy id in reader copy. `strategy.md` carries **43 inline `(strategy:x.y)` cross-references** *inside quotable sentences*, so a quote spanning one fails the first check if it drops the tag and the second if it keeps it. sisay's decision 002 sat broken between them — invisible, because neither validator was wired into a test. The tag is APPARATUS, not prose: `_normalize_ws` strips it from **both sides**, which makes an eliding quote verbatim and leaves the reader-copy lint free to keep banning the id. Neither rule bends.
- **~30 TESTS IN THE SUITE COULD NOT FAIL, AND THAT IS THE MECHANISM EVERY OTHER RULE HERE DEPENDS ON.** A full audit of 110 files found four shapes. **Tests that test themselves**: `test_engine_online_is_measured_not_multiplied` **never called `diagnostic.engine()`** — it copied the `required` filter and the joint count out of `diagnostic.py` and proved that a joint differs from a product, which is a fact about arithmetic; changing `_engine` to multiply left it green, and it *also* skipped when no deck declared `required`, which is 1 of 13, so the flagship metric's only control was one artifact edit from never running. `test_sim_branch_seat` copied `forge.py`'s win tally **character for character** — the expression the documented 0-wins-out-of-11 bug lived in. Four `cluster_regions` tests asserted keys on a dict the test's own helper had just set. **Tests executing zero assertions**: `test_an_off_identity_card_is_refused` was guarded by `if not row["legal"]` against FIVE-COLOUR ur-dragon, so the branch had never once run; `test_a_failing_gate_names_the_artifact` passed precisely when no gate was failing. **14 vacuous loops** with no non-empty guard — three written in the same spike as this note — and **9 cwd-relative globs** evaluated at collection time, silently empty from any other directory. Fixes: drive the production function (each proven by re-introducing the bug), the `assert checked >= N` idiom the repo already used at `test_pilot_validate_stack.py:293`, `ROOT`-anchored paths, and `except FileNotFoundError` in place of `except Exception: continue`, which had made a deck that CRASHES the code indistinguishable from one that is absent.
- **THE THREE CHECKS THAT WOULD HAVE CAUGHT THE SPIKE'S OWN DEFECTS — `tests/test_metric_hygiene.py`.** (1) **No two axes correlate above 0.90 fleet-wide.** It must run under UNIFORM model flags the way `benchmark` does: read off each deck's own declaration only **2 of the 9 axes are computable fleet-wide**, so a check on the declared readings would silently cover 2 of 9 while looking thorough. (2) **Every key `classify()` emits is subscripted somewhere outside it** — an AST sweep, with the one idiomatic exception whitelisted BY NAME, because a silent whitelist is how this check rots into the thing it replaced. (3) **No aggregate pools runs with different opponent sets.** Each proven by re-introducing its defect: the duplicate axis reports `board_power_6 ~ damage_8: r=+0.97`, the dead flag is named, and both go quiet when reverted.
- **A SAFETY COPY IS NOT AN ARTIFACT.** `check-in` writes `decklist.txt.bak` before overwriting — correct, and it was neither tracked nor ignored, so a `git add -A` swept it into a commit and it became a tracked stray. `test_every_tracked_per_deck_artifact_is_documented` caught it, which is the gate working; the file should never have been committable. Gitignored now, alongside `pool.txt`.
- **A validator wired into nothing is not a gate, and this repo has now learned it twice.** `test_pilot_tracked_artifacts_validate.py` gated seven artifacts; `validate_build`, `validate_stack`, `validate_deck` and `validate_goldfish_targets` ran nowhere. Two tracked artifacts were failing their own validator at the time: yawgmoth's `build_plan.json` named a pool directory a rename had moved out from under it, and sisay's decision hit the conflict above. `validate_stack` needed a SEPARATE per-deck case because the map is keyed by artifact filename and it takes a slug and walks two directories — that shape is exactly why it was skipped. Both new gates were proven to fire by re-breaking the artifacts.
- **A test suite is only proven on a machine that has never run the pipeline.** `git clone` into an empty directory, `make setup`, `make test` — the first time anyone did that, **23 tests failed**, and every one was a correct test with a missing gate: five read the pool through `card_pool` (the only reader of the gitignored `cards.csv`) and eighteen validate `strategy:` citations against a DB that is built locally. None of them could ever fail on a developed checkout, because the artifacts are always there. A fresh clone is also *faster* — 20 s against 36 s — because 129 cases gate out. Re-clone whenever you add a test that touches `data/`; nothing else finds this class of defect.
- **The test cache is real and it is not allowed to be silent.** `tests/conftest.py`'s `unchanged(*paths)` skips a regenerate-and-compare test when every named input is byte-identical to the last PASSING run — 90,000 goldfish simulations, nine manual renders and 63 validator runs, ~27 s. Five properties keep it from being a place false confidence lives, and each was proven rather than argued: the key covers the SOURCE of the code under test (editing `goldfish.py` invalidated exactly 1 of `test_pilot_imports`' 77 cases, and reverting invalidated exactly 1 again); a failing test never records (corrupt an artifact and it fails on all three of three runs); a corrupted artifact changes the key, so it re-runs and fails rather than hiding; `.pytest_cache/` is gitignored so a hit cannot reach another machine and CI runs everything by construction; and the run prints `N test(s) served from the cache`. **Name inputs conservatively** — `src/manamap/pilot` whole, not a hand-traced import list. A missed transitive edge does not fail, it serves a stale pass. That tuple is a verified closure: no module under `pilot/` imports from anywhere in `manamap` except `manamap.pilot` and `manamap.config`.
- **THE BLIND-SPOT LIST WAS ITSELF HALF WRONG, AND OVER-REPORTING IT IS THE SAME FAILURE AS OMITTING IT.** `treasure_sources_not_modelled` exists so a low hoard figure is LEGIBLE — and it was built from `treasure_profile` alone while the model has **three** ways to see a Treasure: the trigger table, `treasure_bonus` (a MULTIPLIER — Xorn, Jolene, whose bonus feeds every creation event) and `combat.attack_treasure` (Goldspan, Old Gnawbone, Ragavan) once `model_combat` is on. On ur-dragon's treasure branch it named **nineteen** sources invisible when **eight were being simulated**, and a pilot weighing cards was told the model could see less than it could. A card is blind only if EVERY channel is blind. Verified before regenerating: **only the list moved, every simulated figure is byte-identical** — which is the check that matters here, because gishath's `mean_cast_turn` is quoted sixteen times across seven tracked artifacts.
- **WHAT IS GENUINELY LEFT IS FOUR KINDS OF BLIND, AND ONLY ONE IS STRUCTURAL.** After the fix, eleven sources on that branch: **4 ACTIVATED** (Collector's Vault, Monument to Endurance, Reckoner Bankbuster, Treasure Map — a cost to pay, which a resource model could price), **3 DEATH-TRIGGERED** (Atsushi, Gadrak, Pitiless Plunderer — nothing dies in a goldfish), **2 OPPONENT-GATED** (Smothering Tithe, Smuggler's Share) and 2 other. Only the opponent-gated pair is a boundary rather than a gap: a solitaire model has no opponents by construction, so a card that taxes what THEY do can only ever be worth zero here — which is why a recommendation about that class rests on reading the card, and must say so.
- **AN ABLATION WITHOUT A PLACEBO MEASURES THE LIBRARY SHRINKING, AND IT CAUGHT A WRONG FINDING ONE STEP FROM BEING REPORTED.** Removing N cards to price a component makes every remaining card come up sooner, so the deck gets faster BY CONSTRUCTION. Measured on ur-dragon's treasure branch: removing any 8 non-declared cards raised turn-8 damage **+0.92 on average (+0.70 to +1.18)**, and removing the 8 declared MULTIPLIERS raised it **+1.26** — a gap of 0.34 against an MDE of 0.56. Read against the baseline alone that is *"cutting your multipliers kills faster"*: plausible, correctly signed, interval-backed against the baseline, and **entirely wrong**. The same removals on the HOARD axis are the opposite — every placebo moves UP (+0.67 to +1.06) and the multipliers move **DOWN (−0.77)**, so the direction alone establishes it, and the dragon payoffs at **+1.16** sit above the band (five expensive bodies genuinely cost treasure). **A verdict is relative to the placebo BAND, never to the baseline**, and `diagnostic.ablate` always draws one — reporting *"no placebo was possible"* rather than a bare delta when there are too few comparable singles, because a delta with no control reads exactly like a delta with one. **`candidates` is unaffected and that is why**: it substitutes one-for-one and holds the library size fixed. **The finding that survived**: the diagnostic's bottleneck call was RIGHT — the multiplier group is load-bearing on hoard and its apparent cost to the kill was deck size.
- **THE BOTTLENECK BECOMES A POOL — `close`, and the hand-assembled pile was a SYMPTOM.** `diagnose` names a bottleneck component and nothing turned it into candidates: `deck_audit._closers` is the only component-aware miner here and fires only for components flagged `thin`, so it never runs on the eight-member group actually binding ur-dragon's treasure branch. The only route left was the pilot assembling a pile in the Atlas, which is how a Dragon-typal COMBAT pile came to be weighed against a treasure-DRAIN deck and `assess` came to refuse nineteen of twenty-one. **Two routes, reported separately, because they disagree and the disagreement is the information** — the function-space centroid of the component's own members (`embeddings_ability.npy`, where "what does this card DO" lives) and the shared-role signature. A control asserts each finds something the other missed; if they ever agree everywhere one is redundant and nothing in the output would say which. **A SIGNATURE MUST BE SPECIFIC, AND THE OBVIOUS CHOICE IS NOT**: `_closers` takes the most COMMON shared role, which for any component holding two creatures is `threat:body` — **62.4% of the classified corpus** — so asked to widen the multipliers it offered **Birds of Paradise**. Measured across all **91 declared components on the fleet**: most-common lands on a >40% role for **29**, rarest-first for **7**, and those 7 genuinely have no specific shared role. Rarest-first is the rule this repo already validated when mining training positives. The reordering happens in `close`, **not** in `deck_audit`, because that function is also the audit's and the doctor's and changing what it picks would move agent-facing output on every deck as a side effect of a new command. Result on the branch: signature `doubler:tokens`, **6 in the corpus, every one a real token doubler**, with Primal Vigor in both routes. **The raw centroid is not the answer either** — Halving Season and Hosting Season rank top of it and are ACORN cards, commander-illegal, so a miner that returns them looks cleverer and is wrong; legality is checked through `card_pool`, never re-implemented. `--write` fills `data/decks/<slug>/pool.txt`, **the same slot the Atlas `pool/save` writes**, so `assess` and `candidates --pool library` read it unchanged. The function route is absent on a fresh clone (the embeddings are gitignored) and must **degrade and name the missing route** rather than return a plausible half-answer, which is the `libraryNames` fallback bug.
- **A MEMBERSHIP AXIS CANNOT RANK WITHIN A COMPONENT, AND EVERY AXIS WAS ONE.** `candidates.AXES` offered `engine_online_*`, `any_route_*`, `stall` and `land_drop`; a goldfish target asks whether a card was **DRAWN**, so the ninth member of a group moves the reading by the same amount whichever card it is — measured, all eight of ur-dragon's declared multipliers returned the identical **+0.039**. A true answer to "what is one more member worth" and none at all to "which member", which is the question a pilot asks. The goldfish had been emitting four magnitude series all along (`mean_treasures_in_hoard_by_turn`, `mean_damage_by_turn`, `mean_board_power_by_turn`, `kill_by_turn_rate`) and **nothing exposed them**; `diagnostic.output` carries them through and `hoard_6/10`, `damage_8`, `board_power_6`, `kill_by_8` join the registry. **The control is that they SEPARATE where membership tied** — leave-one-out on the eight multipliers spreads **0.651 at turn 10 against 0.000** — and if they ever agree everywhere the axis is not doing what it claims. Three things it forced. (1) **The block is derived from the per-iteration ROWS, not restated from `metrics`**, because a mean with no dispersion beside it cannot carry an interval, and every figure in this document carries one; a test asserts the means agree with the goldfish's own to 3dp so the goldfish stays the owner in fact. (2) **A kill is a RATE and takes a Wilson bound**; a hoard is a MEAN and takes a t interval — they are not the same object wearing different names. (3) **An MDE for a mean is not the proportion's formula**: `p(1-p)` under a hoard of 6.5 is negative and `_mde` died with `math domain error`, so `sd` rides on every magnitude cell and `diagnostic.mde` dispatches on its presence. **THREE OF THE FIVE WERE ONE AXIS, MEASURED THE SAME DAY THEY SHIPPED**: across 13 decks at a uniform harness, board power@6 vs damage@8 **r=+0.97**, vs kill@10 **+0.98**, damage@8 vs kill@8 **+0.92** — exactly the mana family's defect committed again by the person who had just re-read the note about it. Three axes that rank identically are a TRAP rather than a redundancy: sweep on one, sweep on another, get the same order and read it as confirmation. `damage_8` is the only rankable combat axis now — it survives because a kill rate FLOORS OUT (heliod's kill@8 is 0.001 and discriminates nothing) while damage still separates decks that never close. Every series is still REPORTED with the correlation stated beside it, the way the mana note reads. **The hoard is NOT in that family** (r = 0.08–0.25 against all three), which is what makes it a genuine second dimension rather than `consistency`'s mistake again. **Absent ⇒ absent and NAME THE FLAG** — a deck opting into neither model has no hoard and no clock, and the refusal says `model_treasures`/`model_combat` rather than a bare "no reading" that sends the pilot hunting a bug. Honest limit worth keeping: at 2,000 games the hoard MDE is **0.63**, so most single-card swaps are still noise on magnitude exactly as they are on membership — the tool marks them rather than ranking them.
- **A BRANCHED WRITE WITH AN UN-BRANCHED READ, AND THE CONTROL COULD NOT SEE IT.** `goldfish.main` computed `run(args.slug)` — no `branch=` — and wrote to `deck_dir(args.slug, branch)`, so it measured the CHAMPION and filed the result under the branch's name. On ur-dragon's treasure branch that understated the turn-10 hoard **5.29 → 1.32, a factor of four**, in a file whose own `meta.decklist_sha256` named the champion's list the whole time — **nothing compared that field to anything**. It is the exact mirror of the defect `resolve_out_path` documents, and `test_a_branch_run_never_touches_the_decks_own_artifacts` **passed throughout**: it proves the WRITE landed in the right directory and is structurally blind to a read from the wrong one, since the file appears exactly where it should holding another deck's numbers. The second half of the control is now `test_a_branch_run_measured_the_branch_and_not_the_deck` — every measurement a branch writes must record the BRANCH's decklist sha, which is cheap, exact, and catches the whole class; proven by re-introducing the bug. An AST sweep for `main()` bodies that know a branch and call a worker without it flagged eight modules and **seven were false positives** (they pass it positionally), which is the argument for reading each one rather than trusting the sweep. The two artifacts stamp the sha at different depths (goldfish under `meta`, mana-analysis at the top) and the test reads both rather than normalising tracked files to suit itself.
- **`assess` STEP 6 NOW ASKS ITS QUESTION OF EVERY CARD, NOT ONLY THE OPPONENT-GATED ONES.** *"Can any model here see it"* was implemented for the pod-tax class alone, and it is the same question for everything: a sweep prices what the goldfish simulates and prices the rest **only by displacement**, which reads as noise and costs a full 8,000-game run per card to say so. On the 29-card pool `close` proposed, **14 were invisible** — Mana Reflection doubles MANA rather than tokens, Oath of Lieges and Greener Pastures are land-matters cards the centroid pulled in on similar phrasing. Naming them took the pool from 29 worth measuring to **13**. `_channels` asks `goldfish.classify` directly rather than re-deriving, so triage and simulation cannot disagree about what is visible.
- **SIX FUNCTIONALLY IDENTICAL CARDS RANK BY COST, AND THAT IS THE ANSWER RATHER THAN A FAILURE.** With the model finally able to see all six token doublers, the sweep orders them Kaya (mv3) +0.327, Adrix (mv4) +0.258, Primal Vigor / Exalted Sunborn / Elspeth (mv5) +0.184, Bard (mv6) +0.124 — **corr(mana value, Δ) = −0.998**. They all do exactly the same thing, so the only thing separating them is when you can cast it. Worth stating plainly because it bounds what a simulation is FOR: it confirmed functional identity and then added nothing a curve could not have told you. Only Kaya clears the MDE of 0.309, and barely. **Related, on ur-dragon: the branch trades early speed for late inevitability** — against the champion, hoard@10 **+5.29**, kill-by-T6 **−0.083** (0.099 → 0.016), kill-by-T10 **+0.093** (0.595 → 0.688), damage@10 −1.17, every one above its MDE. A clock, never a win rate: the goldfish has one dummy opponent and nothing blocks.
- **A FLAG THE MODEL SETS IS A CLAIM THE MODEL MUST ACT ON — the Aggravated Assault hole, one card class over.** The cast loop spends on rocks, tutors, extra-combat permanents and bodies; **a token doubler is none of those**. `bodies` is the model's proxy for "worth casting" and it reads 1 for Anointed Procession, Parallel Lives and Doubling Season (their text parses as token creation) and **0 for Primal Vigor, which is the identical card** — so Primal Vigor sat in hand for ten turns while carrying the flag that says it changes what the deck produces. **The tell was fifteen candidates returning the byte-identical −0.026** across mana values 1 through 6, which is the fourth time in this subsystem that identical numbers were the signal. Half a fix is the dangerous state: `TOKEN_DOUBLER_RE` had shipped and three of the four enchantment doublers worked, so the flag looked correct. Anything carrying `treasure_doubler` or `treasure_bonus` and castable by no other loop now gets its own pass, under `model_treasures` so the byte-identical contract holds.
- **A SEEDED SWEEP IS PAIRED BY ACCIDENT, AND THAT IS A FEATURE WORTH KNOWING.** `_with_swap` appends the candidate at the END of the list and the shuffle is seeded, so **every candidate lands in the identical shuffled position in every game** — measured, position 34 for all four cards tested. So a sweep compares candidates across the *same* draw sequences: the design is far stronger than the unpaired one `experiment` correctly refuses (a changed 99 changes every shuffle; a one-card substitution at a fixed index does not). It also means **two cards the model cannot distinguish return byte-identical numbers rather than merely similar ones**, which is what makes an identical column a diagnosis instead of a coincidence.
- **A TOKEN DOUBLER IS NOT AN ADDER, AND ONE REGEX FOR THE CONCEPT LIVED IN TWO MODULES.** `goldfish._TRE_EXTRA_RE` matched a single wording — Xorn/Jolene's *"instead create those tokens plus an additional Treasure"* — while `assess._MULTIPLIER`, one module over, matched five. So the model priced **2 of the 8 multipliers ur-dragon's treasure branch DECLARES** and counted Anointed Procession, Doubling Season, Mondrak and Parallel Lives as drawn-and-inert: they satisfied the component and produced nothing. Same shape as the `front_field` DFC bug — two halves of one idea drifting because nothing made them share a definition. `TREASURE_BONUS_RE` and `TOKEN_DOUBLER_RE` are public in `goldfish.py` (which owns the Treasure model; **not** `config.py`, where adding to the frozen vocabulary invalidates a trained net) and `assess` imports both, staying deliberately broader on purpose. **Doubling is MULTIPLICATIVE and `treasure_bonus` was additive** — they agree only when an event makes exactly one token, which is why an additive stand-in reads almost right; the control is a three-Treasure event under a doubler, which must be **6 and not 4**. Two doublers **compound to ×4**, each replacing the other's output. Order is `(n + bonus) × multiplier`, the player-optimal ordering of replacement effects. **Panharmonicon and Academy Manufactor are deliberately NOT doublers**: the first doubles ETB *triggers* and the second converts a Clue/Food event into a Treasure one (*"instead create one of each"* leaves a Treasure event making exactly one Treasure), so both stay blind and get NAMED — folding them in would be wrong in a way that reads as right. Measured on the branch: turn-10 hoard **5.29 → 6.49 (+23%)**, and every non-opted deck byte-identical, asserted fleet-wide.
- **A DECLARATION WITH NO `required` MARKING DISABLES THE ENGINE FIGURE SILENTLY, AND THE VALIDATOR PRINTED A CLEAN OK OVER IT.** `diagnostic.engine` needs to know which components a deck cannot function without; absent that it withholds the figure — correctly, and out of sight of anyone running `validate-goldfish-targets`. Measured 2026-08-26: **1 of 13 decks** carries the marking, so `engine_online` and every axis built on it were validated on a sample of one. REPORTED, never failed, on the scaffold note's reasoning exactly — a declaration without it is a legitimate older file, and a gate that reddens twelve correct artifacts teaches its reader to ignore the gate. **The test drives `main`**, because the first cut re-derived the rule inside the test and was therefore testing itself.
- **`calibrate` ASKS WHETHER ANY OF THIS PREDICTS ANYTHING, AND ITS ANSWER TODAY IS A REFUSAL.** Every figure in the suite is internally consistent and **none is validated against an outcome**. Forge is the only ground truth and there is almost none: **6 seats have any games, 4 have ≥20**, and `Spearman(Forge win rate, kill-by-8) = −0.10` over the five that exist. That is not a validation, it is the absence of one, and nothing said so out loud before. So the command **refuses a coefficient below 10 decks × 20 games** and prints the gap plus the command that would close it — at n=5 a Spearman needs |ρ|>0.9 for p<0.05, at n=10 it needs 0.65, so a number printed at n=4 is a null wearing a finding's clothes, which this repo has rejected in three other places. Three things it gets right on purpose: **heliod is EXCLUDED, not down-weighted** (8 games reads 0.250 against a fleet spanning 0.00–0.21 purely on n, and including it flipped the sign of the only rank order available); **opponent seats are excluded** because a fetched EDHREC average list has no goldfish figures of its own and correlating one is the easiest way to manufacture a relationship; and **the combat family is represented once**, since correlating power, damage and kill would be one test counted three times. It is also the argument for where compute goes: the whole deterministic layer is **53s per deck against a 5–10 minute budget** — we use ~6% of it — and the only thing that blows the budget is Forge, which is the only thing with external validity.
- **THE MANA MODEL WAS COLOURLESS, AND `mana_analysis` HAD ALWAYS SAID IT MATTERED.** `spend()` took a scalar, so a five-colour Ur-Dragon and a mono-green Radagast with the same land count had identical curves — while one module over, the closed form said the BINDING colour is available on curve only **56%–99%** of the time (median 82%; ur-dragon's black 56%, heliod's white 58%). The simulation cast at 100%. It is not opt-in the way Treasures are: **every deck has colours and a colourless mana model is simply wrong**, so `model_colors` defaults ON and exists to be measured against, not declined. **IT VALIDATES AGAINST A METHOD THAT SHARES NO CODE — the first external check this suite has ever had.** Across 11 decks, `corr(hypergeometric binding-colour P, relative drop in commander-by-six) = **−0.710**`: every deck the closed form calls fine moves ≤0.6% (radagast 0.0%, goblin-storm 0.0%, hapatra 0.1%) and the ones it calls screwed move most (heliod **18.0%**, ur-dragon 13.4%). A test asserts that correlation and says what a break would mean — one of the two is then wrong about colour and the test cannot say which. **A CASTING PIP IS NOT A MANA-BASE PIP**: `manabase.count_pips` half-charges a hybrid to each side and is right to, because that answers *how big a base does this need* and a full pip to both over-builds — but **half a pip is not a thing you can pay**, so `cast_pips` returns one colour-SET per pip and `{2/W}` constrains nothing (a deck with the mana always has the two generic). Same one-concept-two-questions split as `bodies` vs `creature_bodies`. **The greedy assigns the MOST-CONSTRAINED pip first** and gives it the source with the fewest colours: taking `{W}{U}` in written order spends the WU land on the pip a mono-W source could have paid and then reports a castable spell uncastable. Treasures are wildcards. Cost: **+6% runtime** (3.33s → 3.53s at 10,000 games). **This ran OPPOSITE to the rock blindness above**, so before both fixes the two partly cancelled and the total looked plausible while each half was wrong — which is why fixing one alone makes the numbers look worse and is still right. Bug it shipped with: `targets_doc` was bound inside `if targets_path.exists()`, so every declaration-less deck — the benchmark's whole fleet path — raised `UnboundLocalError`.
- **THE GOLDFISH COULD NOT SEE 65% OF THE FLEET'S MANA ROCKS, AND IT WAS A REGEX.** `_TAP_ADD_RE` matched an explicit symbol list and nothing else, so `{T}: Add {C}{C}` parsed and `{T}: Add one mana of any color` did not — **71 of 110 tap-for-mana cards read zero**: Arcane Signet ×7, Birds of Paradise ×5, Relic of Legends, Sanctum Weaver. ur-dragon's model could see **2 of its 11** non-land mana. Turn-seven mana came out low on every deck (sisay 6.55 → **7.66**, ur-dragon 5.59 → 6.20, hapatra 6.72 → 7.23) and commander cast turns 0.1–0.26 late. **This was never a stated assumption** — the module's list names rituals and cost reducers and says nothing about rocks, because nobody knew; a silent half-working regex is the most expensive kind, since it produces a plausible number that is wrong by a fifth. It also taints the recorded finding *"you were never failing to cast things; you were failing to have mana"*, which was derived from a model undercounting mana by 19%. **WIDENING IT INTRODUCED TWO REGRESSIONS AND ONLY A CORPUS SWEEP FOUND THEM.** (1) **A cost that consumes the permanent is not a rate**: `{T}, Sacrifice this artifact: Add three mana` is Jeweled Lotus, and the model would have collected three every turn forever — Kaleidostone, Lotus Bloom and Transmogrant Altar too; `_CONSUMING_COST` refuses sacrifice/exile/discard while allowing a mana cost, since a filter is a real rock. (2) **Alternatives are a choice, not a sum**: `Add {R}, {G}, or {W}` is ONE mana and the widened match counted three — the old narrow pattern got this right BY ACCIDENT, because `(?:\{..\})+` stopped at the first comma, so the fix had to preserve behaviour it was never trying to change. Take the largest consecutive run. Net over the whole corpus: 335 nonland cards newly counted, **2 that now count less** (both were over-counted before), and every card reading 3+ is a real 3-mana rock. **Restricted mana is still counted as free and is now NAMED** in `meta.restricted_mana_counted_as_free` — `spend()` is a scalar and cannot express "only to cast Dragon spells"; Delighted Halfling's legendary-only mana is nearly free in Commander and Throne of Eldraine's four is not.
- **A MODEL FIX LEAVES 39 STALE FIGURES IN AUTHORED PROSE AND NO GATE FIRES.** Regenerating the fleet moved `mean_cast_turn` on seven decks, and four of them quote the old scalar in prose an agent wrote — gishath's tutor guide ×3, heliod's strategic frame ×3 and a decision spread ×2, sisay across four artifacts, radagast's diagnosis. **`validate-diagnosis`, `validate-strategic-frame` and `validate-tutor-guide` all pass**, because none re-derives those scalars. - **`make manuals` HAD BEEN FAILING BEFORE IT REACHED `build-index`, AND CI GATES ON IT.** The recipe ran `test -f data/decks/$slug/issue.json && build-manual $slug` in a `for` loop, so the loop's exit code is the LAST iteration's — and `zur-enchantress` sorts last and has no `issue.json`. Every manual rendered, then make aborted before the manifest step, which is half of the determinism gate. It fires only when the alphabetically-last deck lacks an issue, which is why it survived: a deck added anywhere else in the alphabet hides it completely. `if … then … fi` instead of `&&`.
- **THE CORPUS NUMBER IS NOT THE FLEET NUMBER, AND QUOTING ONE FOR THE OTHER TURNED ONE CARD INTO A FINDING.** A retrospective recorded "**34 of 50 extra-combat cards are invisible**" as a live gap. True of the CORPUS; the fleet runs **three** such cards and exactly **one** is invisible (goblin-storm's Great Train Heist). Same for the token multipliers: `TOKEN_DOUBLER_RE` missed Ojer Taq, and **no deck runs one**. - **AN EXTRA COMBAT THE MODEL CANNOT PLACE FELL THROUGH BOTH BRANCHES AND SET NOTHING.** Neither activated (no mana cost binds) nor triggered on an attack — a one-shot spell (*"After this main phase, there is an additional combat phase"*), or a permanent keyed on being BLOCKED, on exert, on landfall, on a loyalty ability. The model has no channel for any of those, which is a boundary rather than a bug; but the card contributed nothing to the clock AND appeared in no not-modelled list, so a low kill figure was illegible. It sets `unreadable` now — the contract `treasure_sources_not_modelled` keeps.
- **"CONSERVATIVE" IS TRUE OF SPEED AND FALSE OF COMPARABILITY, AND ONE WORD HID THE DIFFERENCE.** The assumption list said *"extra card draw is not modeled (conservative)"*. Drawing one card a turn understates every deck — safe — but by an amount **proportional to how much draw the deck RUNS** (heliod 16 cards, gishath 7), so it is conservative WITHIN a deck and not neutral BETWEEN them, and `benchmark` ranks decks. **Modelling it was measured and refused**: of **146 draw cards on this fleet, 5 are unconditional**. The other 141 are triggers, activations and costs — Rhystic Study needs opponents, Yawgmoth needs a sac outlet and a creature. A model seeing the 5 would cover **3.4%** of the axis while letting the assumption list claim draw was modelled, which is worse than the refusal. `meta.card_advantage` reports the per-deck count instead, because what a reader needs is the SIZE of the gap — there is no figure to make legible, since card advantage is measured nowhere in this suite.
- **NOTHING KNEW WHICH MODEL PRODUCED A FIGURE — `meta.model_version`.** Artifacts stamped the DECK, the seed, the iterations and the turn limit, and never the simulator. So regenerating the fleet after the mana-rock and colour fixes left **39 stale figures in authored prose across four decks** while `validate-diagnosis`, `validate-strategic-frame` and `validate-tutor-guide` **all passed**: the decklist sha had not moved and nothing could tell. It is a **sha over `goldfish.py`'s own bytes**, the trick `conftest.unchanged()` and `agent_cache` already use — deliberately not a hand-kept integer, because a version somebody must remember to bump is one that will not be. **Coarse on purpose**: a comment edit bumps it and costs a regeneration nobody needed, which is the cheaper mistake than a curated list of "model-facing" lines. The three prose validators now carry a **REPORTED, never failed** note — a gate that reddens prose that was correct when written demands either a ~2.5M-token re-spawn or a hand-patch, and hand-patching agent prose to green a gate puts a fresh claim under an old byline. **Three states and only one is evidence**: figures stale, prose written under an older model, and *no stamp at all* — which predates stamping and reports as UNKNOWN, because reddening every agent artifact in the repo on day one is how a gate teaches its reader to ignore it.
- **A Treasure is not a mana rock, and most Treasures are invisible to a goldfish.** `goldfish.py` models a one-shot **stockpile** spent only when lands and rocks fall short — a rock produces forever, a Treasure produces once. Only triggers this model can SEE are counted (upkeep, landfall, cast, Saga chapters, ETB): it has no combat and no opponents, so **16 of the 19 Treasure sources across the nine decks produce nothing**, and a naive `create a Treasure token` match would have handed eight decks free mana they never get — turning a deliberately conservative model optimistic, which is worse than blind. Unmodelled sources are NAMED in `meta.treasure_sources_not_modelled`. Ur-dragon's four Treasure Dragons are all combat-gated and all report zero, which is the most useful thing the model says about that deck. **Opt-in per deck** (`"model_treasures": true` in `goldfish_targets.json`) for the reason `OPTIONAL_DEPARTMENTS` existed: on fleet-wide it moves three decks, and gishath's `mean_cast_turn` alone (7.969 → 7.912) is quoted **sixteen times across seven tracked artifacts** including an `engine.json` carrying a critic verdict. Off, the keys are **absent rather than zeroed**, so a non-opted artifact is byte-identical to before the model existed — verified across all nine — and a WARNING names what is being ignored so nothing sits un-opted by accident.
- **The goldfish did not goldfish, and an entire class of card was priced at zero.** For most of its life `goldfish.py` modelled resource development while calling itself a goldfish — no combat, no opponents — so attack triggers, additional combat phases and every combat-gated Treasure source scored **exactly nothing**. On ur-dragon that was nine of fourteen Treasure sources and **both halves of the deck's only checker-verified win line**, which is how a 20-card rebuild could measure as an improvement on every axis while moving the deck's actual kill rate by 0.2 points. `"model_combat": true` in `goldfish_targets.json` adds one opponent at `GOLDFISH_OPPONENT_LIFE` (40) who does nothing: swing with everything not summoning-sick, fire attack and combat-damage triggers, buy additional combats, and report a **`combat` block** — `mean_board_power_by_turn` (the weighted metric that body count could never be), `mean_damage_by_turn`, and a `kill_turn` distribution. Measured on ur-dragon: the tracked list **never closes by turn ten in 57.8% of games**, the rebuild in 25.9%, and kill-by-turn-8 goes 10.1% → 36.8%. **Same opt-in contract as `model_treasures` and for the same reason** — it changes `mean_bodies_by_turn` on every deck that makes non-creature tokens (all nine), and those figures are published prose on five decks plus a critic-verdicted `engine.json`; all nine are byte-identical with the flag absent, asserted by a test that also fails if a deck opts in behind its back. Three things it gets right on purpose: **a Treasure is not a body** (`creature_body_count` rides WITH the flag, never ahead of it — uncorrected it was 37% of ur-dragon's reported turn-six board), **one opponent not three** (summing a pod invents a number the model cannot support, so `kill_turn` is a clock and never a win rate), and **nothing blocks**, which makes the clock optimistic and is stated in `model_assumptions` rather than buried. Unreadable triggers are NAMED in `meta.combat_effects_not_modelled` — Ancient Gold Dragon rolls a d20 and always will. **The bug this shipped with is the lesson**: `_ACTIVATED_COMBAT_RE` bounded on `[^.]`, and Aggravated Assault reads "…untap all creatures you control**.** After this main phase, there is an additional combat phase" — the period broke the match, so the deck's only verified win line had its extra combats silently unmodelled. A test written from the printed card text caught it; a test written from the parser's output never would.
- **Lowering a deck's curve does not make it faster; its mana base does.** Measured three ways on ur-dragon with the simulator, 10,000 games each: swapping twelve spells for twelve averaging **three mana cheaper** moved turn-five mana by **0.02** and made the turn-six land drop slightly *worse*. Swapping the same twelve for three lands and four cheap accelerants moved it **+0.27** and bought **seven points** of turn-five land drop. You were never failing to cast things; you were failing to have mana. Keep this beside `deck-audit`'s "mana at the point of deployment" verdict — it is what that sentence looks like when tested.
- **A `deck_status` stage whose artifact exists for another reason cannot be checked by file presence.** `pilot-panel` writes `editors_letter` and `pilots_log` INTO `manual_prose.json`, which the `prose` stage already created — so a file-existence stage would report every deck complete the moment the *writer* ran. It was checked by KEY instead (`KEYED_STAGES`). This was caught late and it is the exact failure `deck-status` exists to prevent, one level down: the front of book and `considering_art.json` shipped on all nine decks while the command reported nine complete decks that did not list them. The panel stage and the keyed mechanism left `STAGES` together when `pilot-panel` was retired (2026-08-19) — bring the mechanism back with the first stage that needs it, not before.
- **A stack entry is named under `object` OR `item`.** 53 entries in the corpus use one key and 11 use the other (radagast 8, yawgmoth-swarm 3), and `render_board_block` read only `object` — so eleven entries published as an empty `<b></b>`, an unnamed thing on the stack in the department whose job is showing what is on the stack. `stack_entry_text` accepts both. Do **not** normalise the scenario files: a scenario block is a cache fingerprint input, so tidying 42 files would MISS every stack routine and cost 42 respawns to change nothing a reader can see.
- **The dashed line reaches the prose.** `engine.json`'s `lines[].verified_by` is nullable, the renderer draws a null one **dashed**, and `pilot-panel`'s charter forbids the panel from ASSERTING one — it may discuss it, argue about it, or say nobody has checked. That is the evidence contract reaching past the picture into the copy, and it is the reason the Pilot's Log is worth having rather than being three essays. The panel's own tier is `("coach",)` and not all three: a department's tier is what it GRANTS, not what its speakers mention, or a conversation becomes somewhere a new verified claim can be smuggled in wearing three voices.
- **The engine is not the clusters, and this was measured before it was built.** `deck-map` groups cards by what they SAY; an engine is what cards DO TO EACH OTHER. On radagast only **4 of 10** declared components sit in a single city — the metronome class and the flash traps span five each — so a city name is the wrong address for a component. `manamap pilot engine-facts <slug>` is the deterministic join (deck-audit's priced components + verified pairings from passing stacks via `build_index.line_cards` + contained combo lines deduped on `frozenset` + the scatter table), and `deck-engineer` reasons over it into `engine.json`: eight closed stages, `mana · ignition · fuel · fodder · conversion · output · protection · wincon`. The map is an INPUT it may contradict, and a disagreement is a finding — it means that part of the engine is not visible in card text.
- **`validate-engine` checks that a stack NAMES a line's cards; it cannot check that the stack SUPPORTS the line.** The gap is the sharpest thing about this subsystem and is documented in the module. Two real radagast cases passed every mechanical check: a `mana -> wincon` arrow claiming Castle Garenbrig paid for Craterhoof, citing a stack that leaves Garenbrig untapped; and a line citing a stack whose resolution verifies three NEGATIVES. Both render as **solid green — proof — for a flow the stack shows not happening.** A passing stack is evidence a BOARD resolved a certain way; reading it as causation is inference, and inference is `engine-critic`'s job. Do not close it with string matching: the same wrong line survives a rephrase.
- **A FIELD YOU DID NOT FIND IS NOT A FIELD THAT IS ABSENT — and an orchestrator asserting one is the most expensive kind of wrong.** Ur-dragon's V2 engine round: the critic quoted stack 007's `answers.c`, the orchestrator checked `doc["answers"]` and `doc["resolution"]["answers"]`, found both `None`, and told the engineer **in capitals** that the field did not exist and the quotation was invented. It lives at `resolution.final_state.answers.c`. The engineer had the rebuttal one key away and **deferred to the instruction instead of the source**, so the artifact then asserted twice that a real field was a fabrication — inside the document whose whole discipline is being right about evidence. Three consequences worth keeping. (1) **Defer to the source, not to the orchestrator**: an instruction that contradicts the artifact is answered by showing the field, and both of the two wrong corrections in that round (this and "Farseek never finds a Forest", false because eight lands carry a fetchable type AND Forest) landed because an instruction was taken as the check. (2) **A mechanical "cited field is absent or null" check would have FIRED ON THE CORRECT CITATION** had it resolved `resolution.answers` and stopped — it must walk the full path and report **unresolved**, never *absent*. (3) The real defect was a **short path plus an inexact elision**, not an invented source; diffing the cited span against the field says which, and "fabricated" is a claim that needs the diff before it is made. **Scope widenings compound the same way**: three were ordered on one `map_disagreements` entry and the second was the false one, which is an argument for checking a widening as hard as the thing it corrects — not for refusing to widen, since the original sentence was also wrong.
- **The critic's findings become checks, or its work is re-spent every run.** Round 1 found three `lines[]` whose `from`/`to` stages held none of their `via` cards — an arrow between two stages that is about neither. That is now a mechanical check that catches exactly those lines, on every deck, forever. It also caught the failure this loop exists for: a proposed goldfish edit prescribing the finisher plus FOUR bodies, which is the board stack 003 measured as **not lethal** (36 into 40). The revision split that single line into THE FLOOR (003, loses) and THE THRESHOLD (005, exactly 40, zero margin) — a threshold proved from both sides rather than asserted.
- **A deck's constellation is a LOCAL layout, and the names on it are the deck page's vocabulary.** `manamap pilot deck-map <slug>` re-lays-out one deck's cards from `embeddings_ability.npy` (the FUNCTION space — the layout space knows only colour and type, so a mono-green deck clusters into a green blob and a land pile), then cuts two levels of cities and neighbourhoods. Tracked, because the embeddings are gitignored and a fresh clone must still render manuals. **The rules were measured, and one attribution was later CORRECTED**: the fix that shrank radagast's oversized city is the **balance bound**, not the linkage — the count grows until the largest city is under 35% (Ward on radagast: k=4 54%, k=6 42%, **k=7 32%**, k=9 14%), capped at seven because past that a reader consults a key instead of seeing a shape. Ward is a judgment, not an invariant: at the k a divisor picks it is 38/71 against average linkage's 37/71 — *worse* — and it only leads once k grows (32% vs 49% at k=7). Its apparent no-singleton advantage does not generalise either; on outlier-bearing data Ward strands strays exactly as average does. `tests/test_pilot_deck_map.py` asserts the bound and refuses to assert the linkage, with the reasoning; and territories are drawn **per neighbourhood**, because a spread-out city's convex hull covered every other city and the map read as one continent with labels floating on it. Positions are LOCAL — not atlas positions — and everything that draws this says so.
- **A DIFFUSE lobe gets no territory, and that is a finding rather than a rendering compromise.** Per-neighbourhood hulls fixed the one-continent problem but left radagast's largest lobe drawing a magenta continent down the middle of the frame that *contained* three other cities. Its RMS spread is **0.761 against a 0.153 median — 5x**, and no hull shape fixes a lobe whose members are genuinely everywhere: a hull there asserts a territory that does not exist. Points keep the city colour, the city keeps its label, and the picture then says truthfully "six of these are places and one is everywhere". The threshold is **relative to the deck's own median lobe** (`DIFFUSE_LOBE_RATIO = 2.5`), not absolute, because spreads differ 3x across decks (sisay 0.084, yawgmoth 0.225) while the ratio separates cleanly on all nine — 1–4 diffuse lobes per deck, never a majority. **A city's name then anchors to its tightest SOLID lobe, not to its centroid**: averaging all 23 members of a scattered city drops the name into black space, which reads as a label for the emptiness.
- **A map whose points cannot be identified is decoration.** The printed constellation showed 71 anonymous dots — the web version has hover and the page does not, so a reader could learn only that there were seven groups, which the roster grid below already says better. The commander plus every card named in a checker-passed stack now get labels, greedy AABB, **city names claiming their boxes first** because a city name is the legend and outranks a card. Placement tries eight positions, not two: the load-bearing cards are load-bearing partly *because* they sit where the deck is dense, so the naive above/below slots are exactly the contested ones (2 positions placed 6 of 13; 8 positions placed 10). **Whatever still loses is named in a caption under the figure** — the key promises verified cards are marked, and silently dropping three would make the key a lie.
- **`merge-deck-map` writes `label` and `gloss` and NOTHING else.** `deck_map.json` holds a measurement (positions, membership, verified flags) and editorial (names). A whole-file copy from `.agent-out/` would let a model's paraphrase silently replace the map — a card moved because it seemed to belong there, with every department then describing a cluster the embeddings never found. Same argument `merge_prose` makes, one layer down. `validate-deck-map` then checks names are distinct within a level and that membership still totals; its parent-repeats-child rule binds **only on an agent-supplied label and only where the city actually split**, because a city with one neighbourhood IS that neighbourhood and the deterministic fallback is a description, not a name — the first two versions of that rule fired on five of radagast's seven cities while nothing was wrong.
- **The engine figure is a SCHEMATIC, and every arrow says what it moves.** The first version drew seven boxes joined by anonymous arcs, which states adjacency; an engine is a sequence of *conversions*, and a reader should be able to follow one resource through it — mana buys windows, windows buy bodies, bodies buy cards, cards buy damage. An arrow's noun is the line's own `carries` when the engineer authored one and is **derived from the SOURCE stage** (`STAGE_CARRIES`) otherwise, which costs no schema migration and no ~500k-token engineer/critic respawn; derived labels render **italic** and the caption counts them, because an inference wearing an authored label is what the dashed-line contract exists to prevent. Direction is load-bearing: a forward arrow arcs above the rail and a **backward one arcs below as a feedback loop**, which is what makes an engine an engine rather than a list of steps (radagast's `wincon → conversion` is the finisher pumping the board and the board drawing more cards). Two lines sharing a pair AND a direction are offset apart — radagast declares `fuel → wincon` twice on two different stacks, and drawn identically they are one arrow while the caption still says nine.
