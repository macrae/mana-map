# The magazine renderer (frozen)

The renderer is frozen and its code is not extended. These lessons were measured and are kept for the layout and prose work that outlives it.

Extracted verbatim from `CLAUDE.md` — every measurement here was in that file and none was reworded. `CLAUDE.md` loads into every session; this does not, so the rules that bite regardless of what you are touching stayed there and the full record moved here.

- **A department can now be piloted on ONE deck — `issue_spec.OPTIONAL_DEPARTMENTS`.** Adding an id to `DEPARTMENTS` used to invalidate every issue plan at once, so a department arrived on nine decks or on none; that is what deferred the Coach-department merge and would have forced the Editor's Letter and the Pilot's Log out fleet-wide untested. Optional means **an older plan without it stays valid**, NOT "the editor may skip it" — once a plan carries the department it is validated like any other, and an id should be REMOVED from the set as soon as every deck has it. **Three renderers must agree**: the body skips it, the Flight Plan skips it (the first version did not, leaving eight dead anchors in the one department whose job is telling a reader where things are), and `validate_plan` exempts it. It has carried two migrations and **is now empty, which is the state to keep it in**: the Editor's Letter and the Pilot's Log arrived optional and are on all nine; Act III's three Coach departments (`politics-table` + `know-your-enemy` + `fetch-quests`) merged into one `at-the-table`, all nine moved, and the three originals were **deleted** — spec entry, `ACTS` row, `INTENSITY`/`MODE`/`ACCENT`, renderer and dispatch. A transitional id that outlives its migration is one nobody finished, so `test_the_optional_set_is_empty_until_something_is_being_piloted` fails while the set has members. Two things the emptying broke silently and a test now covers: `PROSE_KEY_DEPARTMENT` still pointed `threat_assessment`/`matchups` at deleted ids, which makes `voices_for` return nothing and the voice lint **pass by finding nothing**; and three renderer tests that iterated `OPTIONAL_DEPARTMENTS` became vacuous, so they inject a synthetic member instead (patching `build_manual`'s own global — it imports the name, so patching `issue_spec` is not seen).
- **The per-byline voice lint, and the two things the fleet deleted from it.** `validate_issue` checks each `pilots_log` turn against its own `voice`, and every other prose key against the voice DERIVED from its department's byline (`issue_spec.voices_for`) — so a byline edit updates it with no second place to remember. A shared department flags only what **both** voices are barred from. **It shipped with the bug this repo has documented five times**: `"very "` as a substring matches `"e-very "`, giving 13 fleet-wide hits every one of which was the word "every" in a correct sentence. Then a second cut on measurement — `really`/`very`/`extremely` went entirely, because hapatra's Ledger writes "a number the deck does not really have", a HEDGE, and no regex separates a hedge from an intensifier. What survived was two genuine `posture` slips in yawgmoth. Run a proposed check against the whole fleet BEFORE keeping it; that rule has now been broken by the person who wrote it.
- **Length is now a measured quantity, and the two numbers disagree on purpose.** Vol. 009 reached **43,494 words and 74.5 screens** of scroll — about 62 A4 pages against a real magazine's 30–50 *including* full-page art. `manamap pilot issue-length <slug> [--rendered]` reports **words** and **visible words** per section, where visible excludes anything inside a collapsed `<details>`. They disagree sharply and that is the point: Judge's Desk was 21.4% of the words and **2.4% of the scroll**, so reading only the first number sends you to cut the appendix — the one department that costs the reader nothing and holds all the proof — while reading only the second hides that the same 120 citations were also printed in The Kill. A length report with one number gives the wrong instruction half the time. The `<summary>` counts as visible: it is the case row on the page, and folding it in with the body reported the appendix at 97 words when a reader does scroll past one line per case.
- **The length budget is calibrated against the fleet, not chosen.** `issue_spec.PROSE_BUDGET` caps each prose key at a length **at least one deck already achieves**, so it is a limit rather than an aspiration — breach rates when set: `how_it_wins` 44%, `mulligan` 33%, `upgrades` 67%, `mana_base` 78%, `combo_lines` 10%, decision `line` 11% / `coaching` 30%. `threat_assessment` and `matchups` are the deliberate exception at 2,500 where the shortest in the fleet are 3,821 and 4,129: that number comes from `validate_engine.MAX_WHAT_IT_DOES = 1800`, and those two are the longest prose in the magazine, run a median above 5,000, and both render in At the Table — which is why one section was ten screens. The Act III merge combined three departments' headers and never touched their prose. Fields the fleet already keeps short take **no cap** (`decision.signals` max 690, `coalition_risk` 639, `card_roles` 365, `pilots_log` turns 1,091), because a check that binds nothing is noise. `validate-issue` REPORTS breaches and `--strict` fails on them: the budget arrived after eight issues were written against none, and failing them all on day one turns eight tracked artifacts red for copy that was correct when it shipped.
- **A LAYOUT fix for a long section is usually a measurement error.** What's Your Play's branch cards render 328px wide and up to 2,486px tall, which reads badly, and the obvious fix — one branch per full-width row — makes the section **taller**: a grid pays only its tallest card per row while stacked rows sum. Measured: 3-up (as shipped) 6,074px, 2-up 6,859px, 1-up 9,520px. The section is long because it holds 2,727 words, and no arrangement of a fixed word count is short. Recorded in `design.py` so the next attempt starts from the measurement.
- **Airiness is bought, not added.** Narrowing the measure to 62ch, opening the leading to 1.62 and doubling the space between sections cost **2.7 screens** — real, and it has to be paid for by a cut somewhere else. Padding added around the same words makes a dense page a taller dense page.
- **A stack title is a resolver's question, not a headline.** They run a median of 74 characters and up to 157, and set at feature size that is three lines of display type before the reader learns anything. `stack_headline` splits on the first colon — across the 49 presentable stacks the head runs a median of **36** characters, only two exceed 60, and the six titles with no colon keep their whole text. The question becomes the dek rather than being dropped. Judge's Desk's case rows use the same head.
- **The Kill's board block renders at reference weight.** It shipped as a grid of bordered cards each holding a `<dl>` and came to **3,782px on radagast — taller than the 4,835px of stack theatre it exists to introduce**, in the issue's most narrative department. `_seat_line` sets the same fields as labelled inline runs, one line per seat: 3,782 → 2,161px, nothing dropped, and "Already paid" keeps its own run because the body count depends on it.
- **The stack theatre is CSS-only, and that is a constraint rather than a compromise.** The Kill rendered its lines as a definition list — a strange thing to do to the most visual object in the game — and now renders the resolution as a receding stack of plates on a vanishing-point grid, one plate per step, hover to lift, click a tab to bring one forward. **No `<script>` anywhere in a manual**: an issue is a standalone printable file that rebuilds byte-identically, so the mechanism is radio inputs plus `:checked ~` selectors and `transform-style: preserve-3d`, and step 1 is `checked` **in the markup** so CSS-off, print and screen-reader readers open on a valid view. The per-index rules are GENERATED into the stylesheet (`_theatre_rules`, bound `THEATRE_MAX_STEPS = 28` against a corpus max of 24) because per-instance CSS means a `<style>` block in every case. Two things it got wrong first: the rail's "RESOLVE" label was a **child** of the tab list, so every `:nth-child(I)` landed one tab early and step 4 showed while tab 3 lit — the label is a sibling now and a test pins it; and the plate stagger was one-directional, so the deck drifted off frame until `--n` centred it. Judge's Desk is deliberately untouched — the theatre is a way *through* the proof, and §5.1 forbids the renderer summarising proof. **The theatre must NOT print citations**: shipping it that way put the identical 120 quotes and all 73 rules into both departments (3,613 duplicated words) and is the exact failure §5.1 names for The Kill. It prints the count and points at the case; a prose *mention* of a rule stays legal and becomes an evidence link. Judge's Desk is now a **case index** — one scannable row per case (`A-00N · headline · status · N steps · M citations`) expanding to the unchanged verbatim record, which is what "Judge's Desk shrinks to verdicts" means alongside "may not truncate a citation". The row deliberately carries **no holding**: deriving one from `final_state.summary` was measured against the corpus and rejected, and that note still stands above `render_the_kill`.
- **The Short List's ten are the only card names an issue could not show you.** Every other card the magazine names is in the 99, so the linker already has its image from `cards.json` and pops a preview on hover; The Short List's subject is by definition OUTSIDE the deck, so its ten rendered as plain text — a recommendation you have to go and google, in the one department whose job is showing you cards you do not own. `manamap pilot short-list-art <slug>` resolves them against Scryfall into a **tracked sidecar** (`considering_art.json`), and `set_card_links(offdeck=…)` gives them the same preview with an external href and a dotted underline. A **sidecar, not a field on `considering.json`**: that artifact belongs to `short-list-analyst` and is fingerprinted per file, so writing art into it would MISS `the-ten` on every art refresh — the same separation `merge_deck_map` makes between what was measured and what was named. **In-deck always wins** when a name is in both. Two things measured: Scryfall's collection endpoint 404s the full `A // B` name for some DFCs (radagast's Disciple of Freyalise) and resolves on the front face — but it answers keyed by the **canonical full name**, so looking the reply up by the face you asked about silently drops the card while reporting "9 of 9".
- **A withheld case still gets an index row, because the issue NAMES it.** Five checker-passed stacks are held back (`presentable: false`) — a card left the 99, so the rules finding stands and the board is one the deck can no longer make. But nineteen times across edgar and yawgmoth, a *published* resolution says "exactly as in stack 001" or "the same lock that refuted stack 001", and stack 001 is nowhere in the issue: **two of yawgmoth's four staged theatres sent the reader hunting for a case that was deliberately not printed.** Judge's Desk now prints a row per withheld case — id, title, and its own `presentable_note` — and no resolution. **The obvious fix, rewriting the referring prose, is the wrong one**: those artifacts passed the checker, so their step text is EVIDENCE, and editing it post-hoc puts a ✓ over words no checker read. A test asserts the renderer does not scrub the reference. 18 of the 19 references sit in the resolution block, which is not cache-fingerprinted, so touching them would have been cheap — cheap and wrong is the trap.
- **The Kill rations the THEATRE, not the argument — `the-kill.features`.** One theatre per passing stack is right at seven and wrong at eleven: yawgmoth-swarm's Kill was **44,119 words, 42% of the issue**, because its loops run 11–14 steps and every one was staged. `features` is an ordered list of stack ids that get a spread; everything else prints under *Also on the record*. **The first cut dropped the authored `combo_lines` intro and printed a bare pointer row, and measuring it showed that was throwing away the wrong thing** — a rendered stack is ~4,000 words and its intro is **77–144**, so the board block and the theatre are essentially all of it. Keeping the intro and the result costs nothing and is the only reading that keeps the department's promise, which is the winning lines *argued*. Result: 44,119 → 19,104 words, 96.5 → 88.4 screens, and The Kill at 20.4% of scroll — the same share it takes on a seven-stack issue. **Word count is a bad proxy for scroll here**: −25,015 words bought only −8.1 screens, because the theatre stacks its plates in Z and is word-heavy, pixel-light. Absent, `features` changes nothing, so no existing issue moves without its plan asking. `validate-issue` fails a non-presentable id, a repeat, and a list naming every stack (that is what omitting the key does, and it rots the first time a stack is added); the renderer **skips** an unknown id instead, because a crash there turns a copy mistake into a missing magazine. An indexed row must carry the `line-<id>` anchor — Judge's Desk prints `↩ Back to this line in The Kill` for every case, and indexing without the anchor makes that a dead jump in the department whose job is being findable.
- **The Pilot's Log runs BEHIND The 99, and the Editor's Letter has its own furniture.** The panel shipped second, ahead of The Command Zone, and was unreadable there for a structural reason: it is the densest thing in the issue and every move refers to material the reader has not met — Sunny's hot take is a contrarian claim about a deck you have not seen, Vera's "that is not established" points at a line you have not read. Order lives **only** in `issue_spec.DEPARTMENTS`, `ACTS` moves with it (a test asserts the flattening), and `validate_plan` DOES check canonical order — so a reorder needs every plan's `departments` array re-sorted, which is mechanical and invalidates nothing. The panel now opens on Sunny's **HOT TAKE** (`kind: "hot-take"` on turn 0, `responds_to: "hot-take"` on a later one, all three checked mechanically; whether a take is *good* is the charter's problem, not a regex's). The letter renders through `letterhead` — wordmark, card, two columns, an IN THIS ISSUE rail, typewriter sign-off, tinted stock — four redundant signals on purpose, because any one alone reads as a styling accident.
- **The Game Plan states its conditions, and the RENDERER decides that, not the plan.** Radagast's thesis read "assemble five bodies, swing for forty" — a correct sum computed on an empty table, modelling no blocker, no removal, no instant and three opponents who do nothing. `not_modelled_rail` is emitted by `render_first_turns` from `engine.json`'s own `open_questions` plus the simulator's scope, so a department whose promise is "why it's going to work" cannot skip the part where it says what it assumed away. Capped at three questions **with the true count stated** — a silent truncation reads as "that's all of them". The nine full goldfish assumptions stay in By the Numbers under the byline that earned them; repeating the set here would sand down the best admission in the issue by saying it twice. The measured pair worth printing on radagast: stack **003 is the floor and it LOSES** (36 into 40, opponent survives at 4) and stack **005 is exactly 40 into ONE seat**, zero margin — and both scenarios' opponents have no creatures, with 003's one seat holding 2/2s annotated *"not blocking"*.
- **A "the Command Zone must not teach the format" lint was measured and REJECTED.** Eight patterns run against all nine decks' `command-zone.body`: the seven targeted ones (`the command zone is where`, `commander tax is`, `your commander is a legendary`, …) score **zero** hits, and the one that hits twice matches a clause that is fine. Meanwhile the defect is real and sits in copy that scores clean — radagast opens *"Your commander begins the game in the command zone and is the only card you always have (CR 903.4)"*, which is true, cited, well written, and a lesson for a reader who has played this format for a decade. No regex separates "explaining the format" from "citing a rule about this commander", because they are the same sentence with a different subject. The rule lives in STYLEv3 §3.3 and the magazine-editor's charter, and the test is the **paste test**: if the first two sentences survive being moved into another issue, they are the wrong two sentences. Recorded in `validate_issue.py` beside where the check would have gone.
- **The 99 groups by city, and shares the map's ink by construction.** `the-99` takes `group_by: "city"`; both the SVG and the grid headings read `CITY_INK` at the same index, so a territory and its block are the same colour. Grouped under plain headings the grid would be a SECOND taxonomy the reader has to reconcile with the picture on the facing page. **`viz/js/deck-view.js` transcribes that palette** for the dossier's interactive version — there is no shared module (the magazine renders with no JS, the page with no Python), so the two lists must not drift or the printed map and the site disagree about which territory is which while both look correct.
- **Never transcribe a registry or its count into a prompt** — `issue_spec.DEPARTMENTS` (legacy), `deck_status.STAGES`, `AGENT_ROUTINES`, `pipeline.STEPS`: read them. The magazine-editor's charter once enumerated the old 15 ids, in the old order, three lines after telling itself to read the spec. `tests/test_docs_section_count.py` fails on any stale count or hardcoded id list.
